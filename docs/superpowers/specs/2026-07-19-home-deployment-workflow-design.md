# 个人主页发布工作流设计

## 目标

把本次已经跑通的个人主页发布链路固化到项目中，使后续代理在收到“发布主页”指令时能够使用一致、可恢复、可验证的流程完成上线。

## 交付物

### 项目代理说明

在项目根目录创建中文 `AGENTS.md`，规定主页发布必须：

1. 检查工作区与发布范围。
2. 执行生产构建。
3. 确认构建产物包含目标变更。
4. 在 NAS 上备份当前线上目录。
5. 上传新的 `dist/` 内容。
6. 验证 NAS 源站。
7. 验证正式域名。

代理说明只保存稳定的非敏感参数，并链接到详细工作流文档和发布脚本。

### 发布说明

创建 `docs/workflows/home-deployment.md`，记录以下固定架构：

```text
浏览器
  → https://home.dailecheng.xyz/
  → 腾讯云 VPS Nginx
  → VPS FRP 端口 22445
  → NAS 192.168.1.210:12445
  → NAS 静态目录 /volume1/web/home
```

文档记录 SSH 用户 `dyf8430`、备份位置、验证方法、缓存处理、常见故障和手动恢复命令。文档不得包含密码、私钥、GitHub 令牌或 FRP 令牌。

### 自动发布脚本

创建 `scripts/deploy-home.sh`，使用 POSIX shell 可用能力和项目现有命令完成：

1. 检查 `pnpm`、`ssh`、`tar`、`curl` 和 `rg`。
2. 运行 `pnpm build`。
3. 从 `dist/index.html` 解析带哈希的 JavaScript 资源路径。
4. 验证该资源存在，并包含 `https://me.dailecheng.xyz/` 与“相册集”。
5. 通过 SSH 在 `/volume1/web/home-backups` 创建带时间戳的线上备份。
6. 通过 tar 数据流把 `dist/` 上传到 `/volume1/web/home`，不主动删除旧哈希资源。
7. 在 NAS 上验证 `http://127.0.0.1:12445/` 引用新的资源，并验证资源内容。
8. 绕过缓存请求正式域名，验证其引用相同资源并包含目标链接和文案。
9. 输出提交版本、备份路径、线上资源名和验收结果。

脚本默认参数固定为本项目当前环境，但允许通过以下环境变量覆盖：

- `HOME_DEPLOY_HOST`
- `HOME_DEPLOY_USER`
- `HOME_DEPLOY_DIR`
- `HOME_BACKUP_DIR`
- `HOME_ORIGIN_URL`
- `HOME_PUBLIC_URL`
- `HOME_SSH_KEY`

脚本不得读取或存储密码；SSH 必须使用已经配置的公钥。

## 安全与恢复

- 覆盖前必须成功创建备份，备份失败立即终止发布。
- 构建或任何验收失败时返回非零退出码。
- 上传不删除线上旧文件，避免破坏未知的运行依赖。
- 恢复时从指定备份包解压回 `/volume1/web/home`，然后重新执行源站和公网验收。
- 不自动修改 VPS Nginx、FRP、NAS 网络或 SSH 安全设置。

## 验收标准

- `AGENTS.md` 为自然、清楚的中文，并正确路由到脚本与文档。
- 发布脚本通过 shell 语法检查。
- 发布脚本支持 `--help`，且帮助信息不触发构建或网络操作。
- 项目生产构建成功。
- 文档中的地址、端口、目录和本次实际跑通链路一致。
- 仓库中不新增密码、私钥或令牌。
