# DLC 空间四子站统一建设设计

## 目标

在现有个人主页仓库中新增四个能够独立部署的子项目，并部署到同一台支持 Docker Compose 的 NAS：

- `blog.dailecheng.xyz`：个人博客。
- `pan.dailecheng.xyz`：个人网盘。
- `nav.dailecheng.xyz`：私人起始页。
- `web.dailecheng.xyz`：公开网址集。

四个子站采用统一的“极光深海”主题和 `DLC 空间` 品牌，同时保留各上游应用成熟的业务能力。现有 Vue 个人主页继续作为独立入口站，本项目不覆盖其已有功能和用户尚未提交的修改。

## 选型与架构

采用“上游应用固定版本 + DLC 主题适配层”的方式：

| 子站 | 基础项目 | 核心职责 |
| --- | --- | --- |
| 博客 | Miniblog | Markdown 文章、标签、RSS、站点地图和代码高亮 |
| 网盘 | OpenList | 文件浏览、预览、搜索、下载、存储挂载和账户登录 |
| 起始页 | Homepage | 搜索、时间、天气、常用入口和服务组件 |
| 网址集 | OneNav | 分类浏览、搜索、后台链接管理和书签导入 |

不重新实现网盘权限、文件操作或书签后台等成熟能力。仓库保存可复现的固定版本、容器配置、初始化配置和主题覆盖文件；上游升级按子项目分别验证，避免四套应用同时发生不可控变化。

计划目录如下：

```text
apps/
  blog/
  pan/
  nav/
  web/
shared/
  theme/
  branding/
deploy/
  compose.yml
  env.example
  proxy/
data/                  # NAS 持久化数据，不提交到 Git
```

根 Compose 统一启动全部服务。每个子项目同时提供独立 Compose 入口，以便单独启动、升级、停止和排障。共享目录只提供设计变量和品牌资源，不共享业务数据库；一个子站故障不得阻止其他子站启动。

## 部署与端口

全部服务部署在同一台 NAS，通过 NAS 现有的反向代理映射到四个域名。项目只提供代理所需的域名、端口、请求头和 WebSocket 配置说明，不主动修改 NAS 设置。

默认外部端口如下：

| 服务 | 默认端口 |
| --- | ---: |
| 博客 | 3101 |
| 网盘 | 3102 |
| 起始页 | 3103 |
| 网址集 | 3104 |
| 起始页认证网关 | 3105 |

端口通过 `.env` 配置。部署前检查端口占用；存在冲突时只修改外部端口，不修改容器内部端口和应用配置。

容器使用明确版本号，不使用 `latest`。每个服务配置健康检查、合理的自动重启策略和日志大小限制。持久化目录统一放在可配置的 NAS 数据根目录下，容器重建和重启不得丢失文章、应用配置、链接或数据库。

## 访问控制

- 博客公开访问。
- 网址集前台公开访问，后台必须登录。
- 网盘必须使用 OpenList 自身账户登录；匿名用户不得获得管理权限。
- 起始页只供本人使用，由独立认证网关在反向代理入口实施登录保护。

网盘与起始页不共用业务账户。域名、密码、令牌、OpenList 存储凭证和 OneNav 数据库不得提交到 Git，统一通过 `.env` 或 NAS 持久化目录注入。

## 统一品牌与视觉系统

品牌规范如下：

- 中文名：`DLC 空间`。
- 英文标识：`dlc`。
- 图标：青绿色渐变圆角方块，内部显示 `DLC`。
- 主题名称：`极光深海`。

主题变量：

- 页面背景：从 `#090e19` 到 `#111a2e` 的深海渐变，并叠加低透明度极光光晕。
- 主色：青绿 `#55d6be`。
- 辅助色：蓝色 `#3b82f6`。
- 主文字：`#eff6ff`。
- 卡片：半透明深蓝背景、细亮边框和背景模糊。
- 圆角：组件使用 `14px`，大容器使用 `20px`。

中文优先使用系统字体，英文与数字采用 Inter 风格字体栈，不依赖外部字体服务。四个子站顶部保留一致的品牌区，但功能导航遵循各应用原有交互。默认采用深色主题；博客额外提供浅色阅读模式，其余应用保持深色，以减少第三方页面适配差异。

动效限制为轻微淡入、卡片悬停抬升和缓慢极光移动，并支持系统的“减少动态效果”偏好。移动端减少背景模糊和大面积光晕，优先保证 NAS 远程访问性能。

## 初始内容

博客预置两篇内容：

- “关于 DLC 空间”。
- 一篇用于展示排版、代码和标签的示例文章。

网盘不创建示例文件，只初始化系统、账户与主题。

起始页预置以下入口：

- 现有个人主页。
- 博客。
- 网盘。
- 网址集。
- 今日热榜。
- 音乐站。

网址集预置“个人站点、常用工具、开发资源”三个分类，并将上述个人站点加入“个人站点”分类。常用工具和开发资源只建立分类结构，不编造用户未确认的网址。

## 故障处理与运维

- 环境变量缺失、数据目录无写入权限或端口冲突时，部署检查应给出可定位的错误信息。
- 上游服务未就绪时由健康检查标记异常，不删除或重建持久化数据。
- 单个容器故障时只重启该服务，不连带重启其他子站。
- 配置升级前备份相应持久化目录；升级失败时允许回退到上一固定版本。
- 认证网关不可用时，起始页保持不可访问，不绕过认证直接暴露服务。

## 验证与验收

实施完成后至少验证：

1. 四个子项目能够分别构建并通过独立 Compose 启动。
2. 根 Compose 能够一次启动全部服务，且健康检查通过。
3. 默认端口可配置，部署检查能够识别端口冲突。
4. 博客与网址集前台可匿名访问。
5. 网盘未登录时不能访问受保护内容。
6. 起始页未通过认证网关时不能访问。
7. OneNav 后台必须登录。
8. 四站均呈现 DLC 标识与极光深海主题，桌面和移动端布局可用。
9. 容器重启后文章、配置、链接和数据库仍然存在。
10. 仓库中不存在真实密码、令牌、存储凭证或运行时数据库。
11. 现有个人主页能够正确跳转到四个子站，且用户已有修改未被覆盖。

## 范围边界

本阶段不包含：

- 修改 NAS 的 DNS、证书或反向代理设置。
- 迁移现有博客文章、网盘文件或浏览器书签。
- 为四个应用开发统一账户系统。
- 重写 OpenList、Homepage 或 OneNav 的核心业务功能。
- 自动升级到未经验证的上游版本。

这些工作可在四个子站稳定运行后分别规划，避免扩大首轮部署风险。
